# 软件著作权申请清单

## 1. 建议的软件申报范围

建议申报本项目自主开发的应用软件，而非将整个 Luna 软件包或上游 RNN 仓库作为申报对象。

建议软件名称：

> `基于UPPE仿真的气体填充反谐振空芯光纤超快脉冲预测与优化软件 V1.0`

建议功能范围：

1. AR-HCF 参数采样、Luna/UPPE 数据生成与 HDF5 数据管理。
2. 光谱数据预处理、特征构建与归一化。
3. Transformer/CNN 对最终光谱和频域演化图的正向预测。
4. 基于代理模型的逆向设计与强化学习优化。
5. Luna 物理验证、最终光谱对比与频域演化可视化。

以下内容不应作为“自主开发代码”申报：

- 上游 `Luna.jl-master/src/` 核心库。
- 上游 `rnnnonlinear` 仓库。
- PyTorch、NumPy、SciPy、Gymnasium、Stable-Baselines3 等依赖的源代码。
- 大型原始数据、模型权重、生成图片和第三方图片。

应使用 `third_party_notices.md` 记录第三方依赖的名称、来源、版本与许可证。Luna 使用 MIT 许可证；如分发其源代码或实质性部分，应保留原版权及许可证声明。

## 2. 先确定申报基本信息

在准备正式材料前，先与导师和单位确认：

1. **著作权人**：学校/研究院、学校与合作单位共同拥有，或个人拥有。若软件依托单位资源并在科研任务中开发，应确认其是否属于职务开发或单位资产。
2. **开发者名单**：应与实际开发记录和项目材料一致。
3. **版本号**：首次申报统一冻结为 `V1.0`。
4. **开发完成日期**：选择 V1.0 所声明功能已经可运行的日期。
5. **首次发表日期**：尚未公开发布时填写“未发表”。
6. **软件名称**：申请表、源代码页眉、说明书封面、页眉和截图中的名称、版本必须完全一致。

## 4. 申请材料清单

### 4.1 软件著作权登记申请表

在统一申请表中准备以下信息：

- 软件全称、简称和 `V1.0` 版本号。
- 著作权人和开发者信息。
- 开发完成日期与发表状态。
- 编程语言：Julia、Python。
- 运行环境：Linux 或 Windows、Julia、Python、PyTorch、可选 CUDA，以及所需的科学计算 Python 包。
- 软件用途、主要功能和技术特点。
- 权利取得方式和权属信息。

### 4.2 源程序鉴别材料

从自主开发模块中准备源代码打印件：

- 通常提交源程序前连续 30 页和后连续 30 页。
- 若全部源程序不足 60 页，则提交全部页面。
- 每页程序通常不少于 50 行。
- 每页页眉标注软件名称和版本号。
- 右上角连续标注页码。
- 使用统一的 A4、黑白打印格式。

应优先选择能体现项目独创性的代码：

1. 参数化 AR-HCF 仿真和数据管理。
2. 光谱预处理和特征构建。
3. 正向代理模型、损失函数、训练和评估。
4. 逆向设计/RL 环境和候选参数导出。
5. Luna 验证和频域演化可视化。

不要让 imports、依赖调用或上游 Luna/RNN 源码占据大部分鉴别材料。

### 4.3 文档鉴别材料

建议提交《软件设计说明书》，也可提交《用户手册》。应尽量准备至少 60 页文档，并按文档鉴别材料规则提供前后各连续 30 页。

建议目录：

```text
封面和版本记录
1. 软件概述
2. 适用范围和使用对象
3. 运行环境和依赖
4. 总体架构
5. 功能模块设计
6. 输入、输出和 HDF5 数据格式
7. 仿真数据生成流程
8. 光谱预处理流程
9. 正向模型训练与预测流程
10. 逆向设计与强化学习流程
11. Luna 验证流程
12. 可视化和结果解释
13. 安装与部署
14. 操作说明
15. 演示实例
16. 测试结果
17. 异常处理与限制
18. 第三方软件和许可证声明
```

建议放入的图片：

- `参数 -> UPPE/Luna -> 预处理 -> Transformer/CNN -> 预测` 工作流。
- Transformer 的 z-token 和波长条件 decoder 示意图。
- RL 闭环：`代理模型 -> 智能体 -> 候选参数 -> Luna 验证`。
- 一张代表性的物理频域演化图。
- 预测与真实结果对比图。
- GUI 截图或命令行工作流截图。

### 4.4 权属和辅助证明文件

按实际情况准备：

- 自然人或法人/组织身份证明。
- 单位任务书、项目立项材料或权属说明。
- 合作开发协议，如适用。
- 对受专有许可证保护的既有软件进行修改时，提供原著作权人许可证明。
- 第三方开源许可证和依赖说明。

下列材料未必都是法定必交件，但对单位审核和补正十分有帮助：

- 软件测试报告。
- 项目任务书或立项证明。
- Git tag、commit hash 和开发记录。
- 可运行 demo 的操作说明。
- 运行截图或简短演示视频。

## 5. 可用于申请表的功能描述

以下文字可作为申请表中“软件功能和技术特点”的基础：

> 本软件面向气体填充反谐振空芯光纤中的超快脉冲非线性传播问题，集成参数化 UPPE 仿真数据管理、光谱预处理、深度学习正向预测、频域演化可视化及代理模型逆向优化功能。软件根据脉冲能量、脉宽、气压、纤芯直径和管壁厚度等物理运行参数，预测输出光谱及传播距离-波长二维频域演化图，并支持通过 Luna/UPPE 仿真对候选参数进行物理验证。

## 6. 申报流程

1. 确认著作权人、开发者名单、软件名称、开发完成日期和 V1.0 功能边界。
2. 冻结代码并创建 `softcopyright-v1.0` Git tag。
3. 构建 `softcopyright_release/`，排除大型数据、权重和上游源代码仓库。
4. 生成 60 页源程序鉴别材料。
5. 编写软件设计说明书或用户手册，并准备文档鉴别页面。
6. 准备第三方声明和权属证明。
7. 准备小型可复现实例、截图和测试报告。
8. 通过单位科研管理流程和相应著作权登记渠道填写、提交官方申请表。
9. 核对所有材料中的软件名称、版本、日期、著作权人和页眉信息是否一致。
10. 归档提交的 PDF、源代码快照、Git tag 与受理凭证。
11. 如收到补正通知，统一修改相关材料；不要在未记录的情况下改动已冻结的 V1.0 源码。

## 7. 本项目近期应完成的事项

1. 确认著作权人应写为学校/研究院还是其他主体。
2. 决定 V1.0 是否纳入当前仍在迭代的 RL 模块。保守方案是先纳入数据生成、预处理、Transformer/CNN 正向预测和可视化；待 RL 验证流程稳定后再作为 V1.0 可选模块或 V2.0 新增功能。
3. 创建干净发布目录和第三方声明文件。
4. 制作小型可复现 demo 数据与输出图。
5. 在最终选取 60 页源程序前，先启动《软件设计说明书》的撰写。

## 8. 官方依据

根据《计算机软件著作权登记办法》，申请软件著作权登记通常需提交申请表、程序和文档鉴别材料、相关证明文件。一般交存的程序和文档鉴别材料由源程序和文档的前后各连续 30 页组成；整体不足 60 页时提交全部材料。除特殊情况外，程序每页通常不少于 50 行，文档每页通常不少于 30 行。

参考：[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)。

本清单用于本项目的材料准备，不构成法律意见。正式提交前，应以单位科研管理部门和登记渠道的最新要求为准。
